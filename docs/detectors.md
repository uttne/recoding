# 検出器

ACF2+、ACF2+→Basic、MPM、pYIN、SwiftF0、Tiny-CREPE、Basic Pitch の単音は、1 フレームにつき 1 つの Hz を返します。和音を入れると、いちばんそれらしい成分が 1 つ返るだけで、音を分離しません。Basic Pitch の重音だけが、同じ時刻に複数の Hz を返します。音名への変換は検出のあと、`src/audio/notes.ts` が行います。

```text
midi = 69 + 12 * log2(hz / a4)
hz   = a4 * 2 ** ((midi - 69) / 12)
```

A4 が 440 Hz のとき、MIDI 69 は 440 Hz です。

エンジンが画面へ渡す点は次の形です。

```ts
type PitchPoint = {
  time: number;          // マイク開始からの秒
  hz: number | null;     // null は無音。重音ではいちばん強い音
  confidence: number;    // その点の信頼度。ACF2+ の有音は 1、無音は 0
  detector: "acf2" | "acf-basic" | "mpm" | "pyin" | "swiftf0" | "crepe" | "basic-mono" | "basic-poly";
  pitches?: { hz: number; confidence: number }[]; // Basic Pitch 重音だけ。強い順
  provisional?: boolean; // ACF2+→Basic の置き換え前だけ true
};
```

## ACF2+

`src/audio/acf2.ts` の `acf2Plus` です。RMS、両端の切り落とし、放物線補間は、Chris Wilson の PitchDetect に入った dalatant の ACF2+ と同じです。探索範囲、重なり数での正規化、いちばん短い強い山、明瞭度はそこで分かれています。Pitchreader と同じ式ではありません。

入力は `Float32Array` とサンプルレートです。窓長は `acfWindowSize` が決め、目標約 50 ms を 2 の累乗に丸め、1024〜4096 に収めます。16 kHz なら 1024、48 kHz なら 2048 です。

| 名前 | 値 | 意味 |
|---|---|---|
| `ACF_FMIN_HZ` | 50 | 探すいちばん低い周波数。最大 lag は `floor(sampleRate / 50)` |
| `ACF_FMAX_HZ` | 4500 | 上限の初期値。画面から 100〜8000 Hz に変えられる。最小 lag は `ceil(sampleRate / fmax)` |
| `PEAK_RATIO` | 0.9 | 正規化した自己相関の最大値に対する割合 |
| `CLARITY_MIN` | 0.3 | 選んだ山を lag 0 で割った値がこれ未満なら無音 |

手順は次のとおりです。

1. RMS が 0.01 未満なら `-1`（無音）。
2. 先頭と末尾を、絶対値が 0.2 未満になる最初の位置まで捨てる。
3. 残った波形の自己相関 `r(τ) = Σ x[i] * x[i+τ]` を、重なり数で割らずに計算する。山の高さの比較だけ `norm(τ) = r(τ) / (size - τ)` を使う。生の総和のまま高さを比べると、項数の多い短い lag が有利になる。
4. lag 0 から生の `r` が下がり続けるあいだ τ を進める。止まった位置を `dip` とする。
5. 探索範囲は `minLag = max(dip, ceil(sampleRate / fmax))` から `maxLag = min(size - 2, floor(sampleRate / 50))` まで。`fmax` の初期値は 4500 Hz で、`acf2Plus` の第 3 引数です。有限な正の数で 50 Hz を超えない値は初期値に戻します。`minLag > maxLag` なら `-1`。
6. 範囲内の `norm` の最大値を `maxValue` とする。
7. 範囲内で生の `r` が両隣以上になる山のうち、`norm(τ) >= 0.9 * maxValue` を満たすいちばん小さい τ を選ぶ。両隣が配列の外に出る τ は候補にしない。候補がなければ、範囲内で生の `r` が最大の τ を使う。
8. `norm(0) <= 0`、または選んだ山の `norm` を `norm(0)` で割った値が 0.3 未満なら `-1`。
9. 選んだ τ と両隣の生の `r` に放物線を当て、`period = τ - b / (2a)` とする。`a = (左 + 右 - 2 * 中央) / 2`、`b = (右 - 左) / 2`。`a === 0` のときは整数の τ のまま。山の位置と補間を `norm` のうえで行うと、48 kHz の 82.41 Hz は lag 582 が 588 へ動き、約 17 セント低くなる。重なり数は、離れた山の高さを比べるときだけ使う。
10. `period > 1` で、`sampleRate / period` が有限な正の数のときだけその Hz を返す。それ以外は `-1`。

エンジンは `-1` を `hz: null` にします。呼び出し間隔は音声時刻で 16 ms 以上です。フレーム間の追跡やメディアンは入れていません。

テストは `src/audio/acf2.test.ts` です。16 kHz と 48 kHz の正弦波 82.41、220、440、880、1000、2000 Hz が 10 セント以内であること、48 kHz の 3000 Hz が初期上限では 10 セント以内で、上限 2100 Hz ではそこへ乗らないこと、1000 Hz に半分の振幅の 2000 Hz を足した波形が 1000 Hz から 50 セント以内であること、振幅 0.001 と無音が `-1` であることを見ています。式やしきい値を変えたら、この許容を更新する前に、なぜ誤差が増えたかをテスト名かコメントに残します。

## SwiftF0

Lars Nieradzik の SwiftF0 0.3 系モデルです。重みは MIT で、`public/models/swift-f0.onnx` に同梱しています。論文は arXiv:2508.18440 です。学習コードとブラウザ向けの説明は upstream の `lars76/swift-f0` と `lars76/swift-f0-training` にあります。

モデルの契約は次です。

| 名前 | 方向 | 型と形 | 意味 |
|---|---|---|---|
| `audio` | 入力 | float32 `[1, samples]` | 16 kHz、振幅はおよそ −1〜1 |
| `fmin` | 入力 | float32 スカラー | 下限 Hz。このアプリは 46.875 |
| `fmax` | 入力 | float32 スカラー | 上限 Hz。初期値は 2093.75。画面から 100〜8000 Hz に変えられ、次の推論から反映される |
| `pitch` | 出力 | float64 `[1, frames]` | 各フレームの Hz |
| `confidence` | 出力 | float32 `[1, frames]` | 0〜1。0.5 以上を有音とする |

フレームは 256 サンプル、つまり 16 ms です。スカラーのテンソル次元は `[]` です。`src/audio/swiftf0-session.ts` がこの形で `InferenceSession.run` を呼びます。

ストリーム制御は `src/audio/swiftf0.ts` の `SwiftF0Stream` です。upstream の `PitchStream` に合わせ、次の定数を使います。

| 定数 | 値 | 意味 |
|---|---|---|
| `SWIFT_LOOKAHEAD_FRAMES` | 10 | フレームを確定する前に必要な後続。176 ms |
| `SWIFT_LEFT_FRAMES` | 11 | 確定後もバッファに残す過去。モデルの受容野 |
| `SILENCE_PEAK` | 0.001 | そのホップの最大絶対値がこれ未満なら信頼度を 0 にする |

モデル自身は無音を落としません。デジタル無音がランダムな有音に見えることがあるため、推論のあとでホップごとにゲートします。ゲートは upstream の `_run` と同じ位置です。

`push` はチャンクをキューに積み、推論が重なっても 1 本ずつ処理します。`flush` は先読みを待たず、残りのフレームを出してストリームを閉じます。`whenIdle` はテストがキューの消化を待つためのメソッドで、画面からは使いません。

16 kHz でない入力は `StreamResampler` が下げます。デシメーションの前に、カットオフを出力レートの 0.45 倍とした一次ローパスを通します。すでに 16 kHz のときはサンプルをコピーするだけです。

有音判定はエンジン側で `confidence >= 0.5 && hz > 0` です。範囲外や NaN の Hz は 0 として扱い、無音になります。

テスト `src/audio/swiftf0.test.ts` はモデルを呼びません。偽の推論関数で、10 フレームでは点がまだ出ないこと、さらに 10 フレームで最初の 10 フレームが出ること、無音ゲートで信頼度が 0 になることを見ています。モデルファイル自体を正弦波で確かめる自動テストは、リポジトリには入っていません。手元で確かめるときは Node 用の `onnxruntime-node` を一時的に入れ、1 秒の 440 Hz 正弦波を 16 kHz で通すと、中央フレームは約 440 Hz、信頼度は 0.5 を超えます。確認が終わったらそのパッケージは外し、`package.json` の依存には残しません。

## MPM

`src/audio/mpm.ts` は npm の `pitchfinder` 2.3.4 の `Macleod` を呼びます。McLeod Pitch Method で、正規化平方差関数（NSDF）の山から周期を選びます。`pitchfinder` は GPL-3.0 です。

| 名前 | 値 | 意味 |
|---|---|---|
| `MPM_FMIN_HZ` | 80 | ライブラリ内部の `LOWER_PITCH_CUTOFF`。これ未満は `-1` になり、画面からも下げられない |
| `MPM_FMAX_HZ` | 4500 | 上限の初期値。画面から 100〜8000 Hz。推定結果がこれを超えたら無音にする。探索範囲自体は変えない |
| `MPM_CUTOFF` | 0.93 | Tartini の設定。いちばん高い山の 93% 以上ある山のうち、最初のもの（短い周期を優先し、倍音へ飛びにくい） |
| 無音 | RMS 0.01 | これ未満は推定しない |

窓長は `mpmWindowSize` が決めます。80 Hz の 2 周期が入るいちばん小さい 2 の累乗で、1024〜4096 です。48 kHz なら 2048 です。`Macleod` に渡す配列の長さは、作ったときの `bufferSize` と一致させます。呼び出し間隔は音声時刻で 16 ms 以上です。信頼度は NSDF の山の高さで、0〜1 に収めます。

テストは `src/audio/mpm.test.ts` です。16 kHz と 48 kHz の正弦波 110、220、440、880、1000、2000 Hz が 10 セント以内であること、1000 Hz に半分の振幅の 2000 Hz を足した波形が 1000 Hz から 50 セント以内であること、上限 2100 Hz では 3000 Hz に乗らないこと、60 Hz と無音が無音であることを見ています。

## pYIN

`src/audio/pyin.ts` は npm の `@audio/pitch-pyin` 2.0.0 の `track()` を呼びます。Mauch と Dixon の pYIN で、YIN の差分関数を 100 個のしきい値（Beta(2, 18)）に通し、0.1 半音のビン上のピッチ HMM を Viterbi で復号します。実装の定数は librosa の pYIN に合わせた、というライブラリ自身の説明です。

| 名前 | 値 | 意味 |
|---|---|---|
| `PYIN_FMIN_HZ` | 50 | `minFreq`。画面からは変えない |
| `PYIN_FMAX_HZ` | 2000 | `maxFreq` の初期値。画面から 100〜8000 Hz。次のチャンクから新しいトラッカーになる |
| ホップ | `round(fs * 256 / 44100)` | 約 5.8 ms。ライブラリの既定 |
| フレーム | 50 Hz の 2 周期が入る 2 の累乗 | 48 kHz なら 2048。時刻は `i * hop / fs` |

フレームは、すべての生存パスがその位置で一致したときに確定します。安定した正弦波ではマイクよりおよそ 0.2〜0.4 秒遅れます。パスが一致しないときは、ライブラリの固定遅延 4096 フレーム（約 24 秒）まで待ち、その後は最良パスで古い側を確定します。点の `time` は確定した時刻ではなく、フレームの時刻です。未確定の区間はグラフで塗ります。上限を変えるとトラッカーを作り直し、未確定の末尾は捨てます。

選択中だけ音声を渡します。切り替えた直後は、もう一度確定を待つことになります。

テストは `src/audio/pyin.test.ts` です。16 kHz と 48 kHz の 1 秒の正弦波 220、440、880、1000 Hz について、中央付近の有音フレームが 15 セント以内であること、1000 Hz に半分の振幅の 2000 Hz を足した波形が 1000 Hz から 50 セント以内であること、上限 500 Hz では 1000 Hz を超える値を出さないこと、ライブの `PyinStream` が 440 Hz を確定することを見ています。

## Tiny-CREPE

Kim らの CREPE の tiny 容量です。重みの系統は MIT で、`public/models/crepe-tiny.onnx`（約 1.9 MB）に同梱しています。`torchcrepe` の tiny を ailia-models が ONNX にしたものです。ライセンス文は `public/models/LICENSE-CREPE.txt` です。

`src/audio/crepe.worker.ts` が Worker 内で推論します。フレームごとの平均と標準偏差による正規化はグラフに入っていて、渡す波形はそのままでかまいません。

| 名前 | 方向 | 型と形 | 意味 |
|---|---|---|---|
| `frames` | 入力 | float32 `[frames, 1024]` | 16 kHz。1 行が 64 ms |
| `probabilities` | 出力 | float32 `[frames, 360]` | 20 セント刻みのシグモイド。ソフトマックスではない |

ビン 0 は 31.7 Hz、ビン 359 は 2005.5 Hz です。`cents = 1997.3794084376191 + bin * 20`、`hz = 10 * 2^(cents / 1200)`。画面の上限の初期値はこの上端で、入力は 100〜2100 Hz です。範囲外のビンはピーク選びと局所平均から外します。モデルはそれより上の音を学習していないので、上限を 2100 Hz にしてもビンは増えません。

復号は `decodeCrepeFrame` です。範囲内で最大のビンを取り、その値が 0.5 未満なら無音です。0.5 以上なら、そのビンの前後 4 ビン（範囲内だけ）の重み付き平均をセントで取り、Hz に戻します。これは CREPE の `to_local_average_cents` と同じ窓です。

`CrepeStream` は 160 サンプル（10 ms）ごとに、中心の前後 512 サンプルを 1 フレームにします。点の時刻は中心なので、そのフレームが揃うのは中心の 32 ms 後です。推論は最大 8 フレームずつ Worker へ渡します。選択中だけフレームを積み、外しているあいだは読み位置だけ進めます。マイク開始時から 16 kHz へのリサンプルは続けるので、選んだ直後から最新のフレームを出せます。

テスト `src/audio/crepe.test.ts` はモデルを呼びません。ビン 228 の山が 440 Hz から 15 セント以内であること、上限 200 Hz と信頼度 0.2 が無音であること、偽の推論でストリームの最初の時刻が 32 ms であることを見ています。

## Basic Pitch

Spotify の Basic Pitch（ICASSP 2022）の `nmp.onnx` です。Apache-2.0 で、`public/models/nmp.onnx`（230444 バイト）に同梱しています。上流の `saved_models/icassp_2022/nmp.onnx` と同じファイルです。ライセンス文は `public/models/LICENSE-BASIC-PITCH.txt` です。

`src/audio/basicpitch.worker.ts` が Worker 内で推論します。調和 CQT はグラフに入っています。

| 名前 | 方向 | 型と形 | 意味 |
|---|---|---|---|
| `serving_default_input_2:0` | 入力 | float32 `[1, 43844, 1]` | 22050 Hz の約 1.99 秒 |
| `StatefulPartitionedCall:1` | 出力 | float32 `[1, 172, 88]` | ノート。MIDI 21〜108。持続する音で高い |
| `StatefulPartitionedCall:0` | 出力 | float32 `[1, 172, 264]` | コントゥア。1 半音を 3 ビン |
| `StatefulPartitionedCall:2` | 出力 | float32 `[1, 172, 88]` | オンセット。このアプリは読まない |

440 Hz の正弦波ではノート頭のビン 48（MIDI 69）が持続し、オンセット頭は頭の数フレームに寄ります。無音のノート頭は 0.2 未満でした。

フレームの時刻は、窓の先頭から `frame * 256 / 22050` 秒です。公式の推論が両端から外すのと同じ 15 フレームを捨てます。残るいちばん新しいフレームは、窓の終わりより約 0.17 秒前です。窓が 43844 サンプル揃うまで最初の点は出ません。その後は、新しい音声が 0.25 秒たまるたびに同じ長さの最新窓を推論し、すでに出した時刻より新しいフレームだけを足します。推論がホップより遅いときは、終わった直後に最新の窓をもう一度走らせます。

重音の読み方は `readBasicFrame` です。

1. ノート頭が 0.3 以上で、左以上かつ右より大きいビンだけを残す。しきい値 0.3 は公式の `DEFAULT_FRAME_THRESHOLD` です。
2. 各ビンの Hz は、コントゥアの `bin * 3 + 1` を中心に前後 4 ビンを重み付き平均して決めます。コントゥアのビン 1 が A0（27.5 Hz）で、ビン `n * 3 + 1` が MIDI `21 + n` です。440 Hz の正弦波はビン 145 に山があり、この式で 440 Hz に戻ります。公式の `midi_pitch_to_contour_bin` は同じ音をビン 144 と数えるので、ピッチベンドをそのまま足すと約 33 セント高くなります。このアプリはモデルの山に合わせています。
3. 平均した Hz が下限 27.5 Hz または画面の上限（初期値は MIDI 108、約 4186 Hz。入力は 100〜4500 Hz）の外なら捨てます。
4. 強い順に最大 8 音です。`pitches` に入り、`hz` はいちばん強い音です。

単音の Hz は `readMonoFrames` がコントゥアの尾根から決めます。各フレームで、直前の音程から ±2 半音（±6 ビン）以内にあるいちばん近い山の重心を取ります。最初の有音フレームは、強いノート頭から順に、その半音の近くの尾根を探します。尾根から 1 半音より遠いノート頭しか無いフレームは無音です。無音の次のフレームは、またノート頭から探します。Hz が下限または上限の外も無音です。有音が続くフレームには、そのあと最大 5 フレーム（前後 2 フレーム、約 58 ms）の中央値をかけます。無音を挟んだ前後は混ぜません。すでに出したフレームは同じ窓の中央値の材料にしますが、出し直しません。

単音は尾根の 1 音だけを `hz` にします。`pitches` は付けません。無音のフレームも点として出し、線を切ります。単音と重音は同じセッションで、復号のときに分かれます。ACF2+→Basic は単音の尾根読みを使います。

テスト `src/audio/basicpitch.test.ts` はモデルを呼びません。ビン 145 が 440 Hz であること、尾根が半音をまたいで数ビンずつ動くと Hz がそれに沿い半音の段にならないこと、ノート頭が尾根から 1 半音より遠いフレームは無音であること、無音を挟んだ中央値が前後の音程を混ぜないこと、三つの山が重音では強い順であること、上限 400 Hz で A4 が消えること、偽の推論で窓の中央から 440 Hz が出ることを見ています。

## ACF2+→Basic

ラジオの値は `acf-basic` です。右端は ACF2+、Basic Pitch の単音が返した時刻より前は Basic Pitch です。大きな音名は ACF2+ の点だけを更新します。遅れて届いたフレームでは音名を変えません。

ACF2+ は、ACF2+ を単体で選んだときと同じ 16 ms 間隔です。上限も ACF2+ の入力を使います。点には `provisional: true` が付き、線の色は ACF2+ の `#e6a15c` です。

Basic Pitch は単音の読み方だけを使います。モデルの読み込み、22050 Hz の窓、両端 15 フレームの切り捨ては Basic Pitch 単音と同じです。フレームが届くと `reviseHybrid`（`src/audio/acf-basic.ts`）が、そのフレームから半フレーム（`256 / 22050 / 2` 秒、約 5.8 ms）以内の暫定点を次の規則で置き換えます。

1. フレームに音があるときは、その Hz を確定点にします。近くの暫定点は消します。線の色は Basic Pitch 単音の `#f0a0b4` です。
2. フレームが無音で、近くの暫定点が Basic Pitch の上限より高いときは、その暫定点を残します。色は ACF2+ のままです。Basic Pitch のビンは MIDI 108 までなので、それより上は ACF2+ の値を残します。上限を下げたときも、その入力より高い暫定点を同じように残します。
3. フレームが無音で、近くに上限以下の暫定点があるときは、無音の確定点にします。線はそこで切れます。
4. 近くに暫定点が無い無音フレームは、点を足しません。
5. 半フレームより離れた暫定点は残します。窓の両端を捨てた区間や、推論が遅れてフレームが飛んだ区間は、ACF2+ の色のままです。

確定した点どうしは、Basic Pitch の単音と同じ 0.75 半音までつなぎます。暫定の ACF2+ どうしは、半音の半分（0.5 半音）を超えると切れます。暫定と確定の境も 0.5 半音です。オクターブが違っていれば、置き換わったところで線が飛びます。未確定の帯は ACF2+ の色で、いちばん新しい Basic Pitch のフレームから右端までです。

グラフの下限は Basic Pitch の 27.5 Hz、上限は ACF2+ と Basic Pitch の上限のうち高い方です。専用の上限入力はありません。

テスト `src/audio/acf-basic.test.ts` はモデルを呼びません。1000 Hz の暫定点が 2000 Hz に置き換わること、上限 4186 Hz より高い 4500 Hz は無音フレームでも残ること、音があるフレームではその高い点を捨てること、上限以下の暫定点が無音になること、枠の外の点と他の検出器の点が残ること、暫定点の無い無音フレームは点を足さないことを見ています。

## 検出器を足すとき

1. `DetectorId` に識別子を足す。`src/audio/engine.ts` にあります。
2. `onChunk` から新しい推定を呼び、選択中のときだけ `onPoint` する。無音は `hz: null` にします。
3. `src/graph.ts` の `COLOR` と `LIMIT_LABEL` に色と名前を足す。`GraphRanges.byDetector` にも範囲を足す。
4. `index.html` の検出ラジオと上限の入力に choice を足す。`src/main.ts` は `input[name="detector"]` の value をそのまま `engine.detector` に入れます。
5. モデルや WASM が増える場合は、`public` へ `.mjs` を置かず、`vite.config.ts` の配信方法に合わせます。詳細は [architecture.md](architecture.md) の「ONNX Runtime の置き場所」です。
6. 式に数値の期待があるものは `src/audio/*.test.ts` に足し、`mise exec -- npm test` で通します。マイクを使ったテストはまだありません。
